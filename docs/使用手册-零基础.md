# 使用手册 · 零基础版

> 这份手册写给**没写过代码的人**。跟着做完，你能自己跑测试、自己看懂结果，
> 还能靠填一张 Excel 表写出新的测试用例。
>
> 想搞懂框架内部是怎么运作的，看另一份：[框架导读.md](框架导读.md)。
> 现在做到哪一步、哪些约定不能丢，看：[交接文档.md](交接文档.md)。

---

## 一、先用一句话说清它能干什么

**它能做的**：

- 连上你插在电脑上的安卓手机，去操作手机上**已经打开**的微信小程序，检查页面显示对不对；
- 每一步自动截图、记耗时，跑完生成一份带图的网页报告。

**它做不到的（先记住，这几条最容易被误会）**：

- 不会帮你打开微信、也不会帮你打开小程序 —— **跑之前要你自己在手机上把小程序点开**；
- 不能输入中文（关键词只能用字母、数字、下划线、点、连字符）；
- 表格里能写的操作有 23 个（见下表「动作清单」），更复杂的流程还是得写代码；
- 不会自己判断「该等多久」：文字断言最多等 8 秒、点击最多等 10 秒，这些数字写在代码里，表格改不了；
- 会改数据的操作（提交、兑换、签到、下单…）默认**不让做**，理由见第八节。

## 二、跑之前，先确认三件事

在项目目录下打开 PowerShell（就是那个黑框），依次敲：

| 敲什么 | 看到什么才算对 | 不对怎么办 |
|---|---|---|
| `adb devices` | 有一行 `xxxxxx  device` | 显示 `unauthorized` -> 手机上点「允许 USB 调试」；一行都没有 -> 换一根能传数据的线、手机上打开「USB 调试」 |
| `node -v` | `v18` 以上 | 去 nodejs.org 装一个 |
| `python -V` | `3.11` 以上 | 去 python.org 装一个（安装时勾上 Add to PATH） |

**第一次用，还要装一次依赖**（只用做一次，之后不用再管）：

```powershell
pip install -r requirements.txt
npm install
```

> 想看到带图的网页报告，还需要 Java 和 allure 命令行（可选）。没装也能跑，
> 只是最后一步会提示「跳过 HTML 报告生成」，截图和结论照样有。

## 三、跑测试：三步

### 第 1 步：在手机上准备现场

1. 打开微信 -> 打开咱们的小程序；
2. 随便停在哪一页都行（**能自动导航的用例会自己走过去**，比如「回到首页」）；
3. 手机别锁屏、别拔线。

### 第 2 步：在电脑上执行

```powershell
python run.py
```

它会把全部用例跑一遍，并生成报告。第一次跑会有几分钟，正常。

只想跑其中一条：

```powershell
python run.py -k 专栏                    # 名字里含「专栏」的用例
python run.py -k 搜索页_001              # 只跑表格里的这一条（表格见第六节）
python run.py suprecast_app/test_example.js   # 只跑点名的那一个文件
```

### 第 3 步：看结果

控制台最后会打印一行总结，形如：

```text
====================== 8 passed, 1 skipped in 320.55s ======================
```

再往下会告诉你去哪看网页报告（`report/allure-report/index.html`，双击用浏览器打开）。

## 四、结果怎么看：三个词

| 你看到的 | 意思是 | 你要做什么 |
|---|---|---|
| **通过 (passed)** | 页面显示符合预期 | 不用管 |
| **失败 (failed)** | 页面显示**不符合**预期，或者操作点不上 | 看报告里的失败步骤 + 截图，拿去提 Bug |
| **跳过 (skipped)** | 这次不适合测（比如答题活动今天没上线） | 一般不用管，但**数量突然变多要当回事** |

> 为什么「跳过」要留意：它不算通过。如果哪天原本能跑的用例全变成跳过，
> 说明环境变了（活动下线、改版、小程序没打开），而不是「一切正常」。

### 报告里每一行都写了什么

打开网页报告，点开任意一条用例，你能看到：

- 用例名字 —— **都是中文**：表格用例用你填的「用例编号 + 用例名称」，
  代码写的用例也有各自的中文名（文件名本身是英文，那是给写代码的人看的）；
- 每一步叫什么、花了多少秒；
- 失败那一步的**报错原文**和**当时的截图**；
- 「用例上下文」：用例中途记下来的信息（例如「刚点的那个专栏叫什么」）。

同一台电脑上，截图还都在 `report/photo_app/` 里按用例分目录存着，
表格用例的截图在 `report/photo_app/表格用例/用例编号/` 下面。

## 五、加自己的用例（不写代码）：填一张表

这是这套框架给零基础用法准备的路子：**在 Excel 里一行一行写「做什么」，剩下的交给框架**。

### 表在哪

`cases/用例表.xlsx`。里面有三张工作表：

1. **用例** —— 你要填的就是这张；
2. **动作清单** —— 能写哪些动作、每个动作要什么参数（这张别改）；
3. **填写说明** —— 一页纸的填表规则。

### 怎么填（记住四条就够）

1. **一行 = 一个步骤**。同一个「用例编号」的若干行合起来是一条用例，按「步骤序号」顺序执行；
2. **必填三列**：用例编号、步骤序号、动作。「用例名称」只在某条用例的第一行写一次；
3. **动作只能填「动作清单」里的名字**，而且那一列是**下拉框**（点单元格右边的小箭头直接选）——
   打错的字根本选不出来，少一轮报错；填了别的也会在导出时当场报错（不会默默跳过那一行）；
4. **参数不用就留空**；该用没填、或者不该用却填了，也会报错 —— 这是故意的，防止手滑填错列。

### 填完怎么跑

```powershell
python run.py                 # 会先自动把表格导出，再把表里的用例跑一遍
python run.py -k 搜索页_001    # 只跑表格里的这一条
```

> 「导出」你不需要手动做，`python run.py` 会自动做。
> 表格有问题时会**当场停下来并告诉你第几行错了** —— 因为如果继续跑，
> 跑的就是上一次的表格，那种「通过」是假的。

### 全部动作速查（23 个，表格里也是这份）

| 动作 | 参数1 | 参数2 | 干什么 | 会改数据吗 |
|---|---|---|---|---|
| 回到首页 | | | 自己导航到「有问必答」首页信息流：在二级页/搜索页会先点返回退出，并**把筛选 tab 归位到「最新提问」** | 不会 |
| 切到用户中心 | | | 点底部 tab「我的」 | 不会 |
| 打开学习中心专栏 | | | 进学习中心并切到「专栏」列表 | 不会 |
| 打开搜索并输入 | 关键词 | | 打开搜索页并输入（关键词只能字母/数字/下划线/点/连字符） | 不会 |
| 打开答题活动 | | | 打开答题活动页 | 不会 |
| 点文字 | 文字 | | 点页面上看得见的某段文字 | **会**（提交类文字已被拦住） |
| 点选择器 | 选择器 | | 按选择器点第一处（文字重名时用它更准） | **会**（同上） |
| 返回上一页 | | | 点返回 | 不会 |
| 滑动 | 次数 | 方向 | 滑屏：次数 1~10，方向填 上 或 下。列表要滑到底用「上」，滑完滚回顶部用「下」 | 不会 |
| 切换筛选tab | tab名 | | 切首页那排筛选 tab（最新提问/推荐/精选问答/我的关注），切完会验证真的选中 | 不会 |
| 切换学习中心顶部tab | tab名 | | 切学习中心顶部 tab（课程/专栏/压铸百科），不在学习中心会自己先过去 | 不会 |
| 点第一张专栏 | | | 在专栏列表里点第一张卡，进它的详情页 | 不会 |
| 等待 | 毫秒 | | 纯等待，例如 2000 | 不会 |
| 打印页面文字 | | | 把当前屏幕上看得见的文字打进日志 —— **不知道检查什么文字时先用它** | 不会 |
| 检查文字显示 | 文字 | | 断言页面上看得见这段文字 | 不会 |
| 检查文字不显示 | 文字 | | 断言页面上看不见这段文字 | 不会 |
| 检查文字出现次数 | 文字 | 期望次数 | 断言这段文字在整页里命中几次（外层包裹也会被算，数字常比肉眼多） | 不会 |
| 检查元素存在 | 选择器 | | 断言找得到这个选择器，例如 .search-container | 不会 |
| 检查元素不存在 | 选择器 | | 断言一个都命中不到（例如首页上不该出现 .activity-quiz-page） | 不会 |
| 检查元素数量 | 选择器 | 期望数量 | 断言命中个数正好是这个数 | 不会 |
| 检查输入框的值 | 选择器 | 期望值 | 读出输入框里真实的值再比较（唯一能「读出来再比」的检查） | 不会 |
| 检查答题页符合需求 | | | 按需求 713594985 校验答题页。⚠️ 只适用于**一道题**的活动；多选题库活动会记成「跳过」并说明原因 | 不会 |
| 检查活动入口 | | | 按需求 713594979 校验活动入口在 4 个筛选 tab 下都显示 | 不会 |

**写用例的小套路**：先「回到首页」把起点摆正 -> 再做操作 -> 最后一定用
「检查…」类动作收尾。只有操作没有检查的用例，是**测不出问题的**（框架里
`test_login_and_navigation.js` 就是故意留的反例）。

### 表格里预置的三个例子

打开表格就能看到这三条，它们可以当模板抄：

| 用例编号 | 做什么 | 说明 |
|---|---|---|
| 活动入口_001 | 回到首页 -> 检查活动入口 | 稳定，真机验证过 |
| 搜索页_001 | 回到首页 -> 打开搜索并输入 test -> 检查元素存在 -> 回到首页 | 稳定，真机验证过 |
| 答题页_001 | 回到首页 -> 打开答题活动 -> 检查元素存在 -> 检查文字显示 -> 回到首页 | 首页轮播里没露出「答题」卡时，这条会记成**跳过**（不是失败） |

注意这几个例子的**首尾都有「回到首页」**：开头那步是给自己摆正起点，
结尾那步是把手机交还给下一条用例。表里的用例共用同一部手机，
上一条停在搜索页/详情页上，下一条就可能报「找不到底部 tab」—— 首尾各加一步就避开了。
另外「回到首页」还会顺手把上面的筛选 tab 归位到「最新提问」：小程序会记住你上次点了哪个 tab，
不归位的话，下一条用例的起点就跟着上一条走了。

## 六、表格填错了，你会看到什么

框架不会笼统地说「你错了」，而是指到行：

```text
用例表有问题（2 处），没有导出：cases/用例表.xlsx
· 第 5 行：不认识动作「打开首贝」。可用的动作（共 23 个）：回到首页、切到用户中心、…
  · 第 7 行：动作「打开搜索并输入」的「参数1」要填「关键词」，现在是空的
```

常见几类对照：

| 报错里出现 | 意思是 | 怎么改 |
|---|---|---|
| 不认识动作「xxx」 | 动作列写了清单里没有的名字（多半是错别字） | 按「动作清单」工作表改 |
| 参数1 / 参数2 要填… | 这个动作需要参数，你留空了 | 补上 |
| 用不到「参数1」 | 参数填多了（常常是把参数填到了备注列旁边） | 清空多余的那列 |
| 步骤序号只能填… | 写了「一」「1.5」这种 | 改成 1、2、3… |
| 有的步骤写了顺序号、有的没写 | 同一条用例里混着写 | 要么全写，要么全不写 |
| 同一个用例编号只能有一个名字 | 同一条用例的两行写了不同名字 | 名字只写一次 |
| 用例表有问题…已停止本次运行 | 表格有错，故意不跑 | 改完再跑；只想跑别的用例就点名文件，如 `python run.py suprecast_app/test_example.js` |

## 七、为什么默认不让点「提交」这类按钮

因为我们用的是**真实账号、真实数据**（这个测试环境没有独立的测试账号）。
点一下「提交答卷」就真的用掉一次机会、真的写进数据库 —— 不是演练。

所以表格里的「点文字」有一道安全阀：**提交、兑换、签到、下单、支付、购买、
领取、抽奖、报名、删除、退出登录、退款、取消订单** 这些字，一律点不了，会直接报错拦下来。

「打开答题活动」也只打开页面：不选选项、不提交（选选项会消耗答题机会）。

真要测这些会改数据的流程，得单独写一条用例、并显式打开开关（那是开发的事），
不建议在表格里随手写一行触发。

## 九、常见问题（照着对号入座）

### 报错里有 `unrecognized arguments: --alluredir`

你用的 Python 环境里少装了一个插件。**在哪个环境跑，就在哪个环境装**：

```powershell
pip install -r requirements.txt
```

如果你是自己建过虚拟环境（目录名像 `.venv`）并激活了它，那套环境是独立的一份，
也得装一次；或者敲 `deactivate` 退出它，改用系统 Python 跑。

### 报错说 `找不到前台小程序webview`

手机上没有打开小程序。按第三节第 1 步把微信里的小程序点开，再跑一次。

### 一条用例都没跑（`collected 0 items`）

多半是在错误的目录下执行了 pytest。**用 `python run.py` 就不会有这个问题** ——
它自己会切到正确目录（必须切的那一步已经写进代码了）。

### `adb devices` 看不到手机

依次检查：手机上「开发者选项 - USB 调试」开了没；数据线是不是只能充电的那种；
手机上有没有弹「允许调试」的对话框。

### 提示「检测到多台设备」

那就明确指定用哪台：

```powershell
python run.py                                        # 先看报错里列出的序列号
$env:UITEST_DEVICE_SERIAL = "3B1F64EA9BBUTE00"       # 再指定用哪台（只对当前这个窗口生效）
python run.py                                        # 同一窗口里再跑
```

> 别写成 `set UITEST_DEVICE_SERIAL=...` —— 那是 cmd 的写法，在 PowerShell 里
> **不报错、但也不生效**（这类「看起来成功了其实没生效」是这套框架最防备的事）。

### 跑到一半，手机界面被别的东西抢走了

这台手机**同一时间只能有一个人跑测试**：另一个 AI、另一个窗口、或者你自己在用手机，
都会互相打断（表现是"点击了但没反应"、页面停在奇怪的地方）。
跑之前先确认没有别人在跑。

### 一次全量跑里有 1 条红了，单独跑它却过了

先别急着改代码 —— 这多半是**偶发**，不是功能坏了。已知的两类原因：

- `adb` 点击偶尔点到旁边的元素（日志里会出现「向上第 N 层找到可点击容器」这样的话）；
- 小程序同时开着好几个页面时，框架偶尔会认错「现在屏幕上显示的是哪一个」。

这两件事都写在 `docs/踩坑记录.md`（坑 15~17）里，框架也加了自愈，但**没有根除**。
遇到时的标准动作：先用 `python run.py -k 用例编号或文件` 单独复跑一次确认；
如果单独跑还是红，那就是真问题，把报错原文（连同上面几行）发出来。

### 输入中文没反应，还不报错

这不是你的错，也不是框架能修好的：输入是通过 `adb` 发过去的，**它先天不支持中文**。
所以表格里的关键词只放行字母、数字、下划线、点、连字符。中文输入的替代方案见
[README.md](../README.md) 的「已知限制」一节。

## 十、术语小抄

| 你看到/听到的词 | 人话 |
|---|---|
| 用例 | 一条测试：一段「先做这个、再检查那个」的流程 |
| 步骤 | 用例里的一小步（表格里就是一行） |
| 断言 / 检查 | 「我确信这里应该显示 X」的这句话；不成立就算失败 |
| 通过 / 失败 / 跳过 | passed / failed / skipped，见第四节 |
| pytest | 跑测试的调度器，负责收集用例、统计成绩 |
| Allure | 生成那份带图的网页报告的工具 |
| adb | 电脑和安卓手机之间的连接通道（点屏幕、截图都靠它） |
| webview / 前台页 | 手机上小程序真正显示内容的那一层；同一时刻可能有多个，得动态找出「正在显示的那个」 |
| 页面对象 | 把「某个页面长什么样、能做什么」写在一个文件里，改版时只改它 |
| 动作清单 | 表格第二张工作表：能写哪些操作 |
| 步骤日志 | 每一步做了什么、花了多久的原始记录，失败时最有用 |

## 十一、一句话回顾

> 手机插上、微信小程序打开 -> `python run.py` -> 看总结那一行 ->
> 要加用例就填 `cases/用例表.xlsx` 再跑一次。

卡住的时候，把控制台里的报错原文（连同报错上面几行）发出来就行 ——
这套框架的报错大多写清了「哪里错、怎么改」。
