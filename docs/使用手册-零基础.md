## 一、先用一句话说清它能干什么

**它能做的**：

- 连上你插在电脑上的安卓手机，去操作手机上**已经打开**的微信小程序，检查页面显示对不对；
- 每一步自动截图、记耗时，跑完生成一份带图的网页报告。

**它做不到的（先记住，这几条最容易被误会）**：

- 不会帮你打开微信、也不会帮你打开小程序 —— **跑之前要你自己在手机上把小程序点开**；
- 不能输入中文（关键词只能用字母、数字、下划线、点、连字符）；
- 表格里能写的操作有 48 个（见下表「动作清单」），更复杂的流程还是得写代码；
- 不会自己判断「该等多久」：文字断言最多等 8 秒、点击最多等 10 秒，这些数字写在代码里，表格改不了；
- 会改数据的操作（提交、兑换、签到、下单…）默认**不让做**，理由见第八节。

## 二、跑之前，先确认三件事

在项目目录下打开 PowerShell（就是那个黑框），依次敲：

| 敲什么 | 看到什么才算对 | 不对怎么办 |
|---|---|---|
| `adb devices` | 有一行 `xxxxxx  device` | 显示 `unauthorized` -> 手机上点「允许 USB 调试」；一行都没有 -> 换一根能传数据的线、手机上打开「USB 调试」 |
| `node -v` | `v18` 以上 | 去 nodejs.org 装一个 |
| `python -V` | `3.11` 以上 | 去 python.org 装一个（安装时勾上 Add to PATH） |

**第一次用，还要装一次依赖**（只用做一次，之后不用再管）：

```powershell
pip install -r requirements.txt
npm install
```

> 想看到带图的网页报告，还需要 Java 和 allure 命令行（可选）。没装也能跑，
> 只是最后一步会提示「跳过 HTML 报告生成」，截图和结论照样有。

## 三、跑测试：三步

### 第 1 步：在手机上准备现场

1. 打开微信 -> 打开咱们的小程序；
2. 随便停在哪一页都行（**能自动导航的用例会自己走过去**，比如「回到首页」）；
3. 手机别锁屏、别拔线。

### 第 2 步：在电脑上执行

```powershell
python run.py
```

它会把全部用例跑一遍，并生成报告。第一次跑会有几分钟，正常。

只想跑其中一条：

```powershell
python run.py -k 专栏                    # 名字里含「专栏」的用例
python run.py -k ZW_002              # 只跑表格里的这一条（表格见第六节）
python run.py suprecast_app/test_example.js   # 只跑点名的那一个文件
```

> ⚠️ **只跑一条，`-k` 不能省**：写成 `python run.py ZW_002` 的话，那个编号会被 pytest 当成
> **文件名/目录**去找 —— 结果"收集 0 条"、退出码 4，报错还把人往"参数格式写错了"上带。
> 现在框架会**拦下来并直接告诉你正确写法**（2026/10/14 加，见踩坑记录坑 39）：
>
> ```text
> [!] 「ZW_002\」是**用例编号**，这样传跑不起来 —— （ZW_002「搜索页能打开并输入关键词」）
>     只跑这一条的正确写法是给它加个 -k：
>       python run.py -k ZW_002
> ```

### 第 3 步：看结果

控制台最后会打印一行总结，形如：

```text
====================== 8 passed, 1 skipped in 320.55s ======================
```

再往下会告诉你去哪看网页报告（`report/allure-report/index.html`，双击用浏览器打开）。

### 换环境：测试 / 生产（每跑一次都会告诉你跑的是哪个）

框架能跑两个**不同的小程序**（测试环境和生产环境，不是同一个东西）。参数写在 `config/env.yaml`，
跑之前自动带上。**现在只跑测试环境** —— 生产那个小程序的 appid 还没填，选它会当场停下（下面说为什么这是好事）。

```powershell
python run.py                 # 跑 config/env.yaml 里 current 指定的环境（现在是 test）
python run.py --env test      # 这一次用测试环境
python run.py --env prod      # 这一次用生产环境（现在会被拦下）
python tools/use_env.py       # 看有几个环境、当前是哪个、各自什么参数
python tools/use_env.py prod  # 把默认环境改成 prod（写回配置文件）
```

每跑一次，**第一行**都会打印：

```text
本次环境：测试环境 · 超云生态平台（压铸人的社区百科）（appid wx3de2e1d179b60303）
```

三条要知道的：

1. **appid 是安全阀**：带上它之后，框架只会操作这个 appid 的小程序；万一微信里开着的是另一个，
   它会**直接报错**，而不是在别的小程序上跑出一片假绿（两个小程序可能同时缓存在这台手机上）。
   怎么确认它生效了：日志里会有一行 `已开启 appid 安全阀：只操作 wx…`。
2. **生产环境现在被拦着**：`prod` 的 appid 是空的，选它会立刻停下并告诉你去哪填 ——
   这不是"没做完"，是故意的：拿不到 appid 就排除不了"其实测到了别的小程序上"。
3. **生产环境不许写数据**：就算你先设了写开关，选 prod 之后它也会被**清掉**（只读）。

> 为什么要有这一套：以前框架跑起来从不声明"我测的是哪个环境"，appid 安全阀写好了却没人给它值，
> 等于**装了但没通电**。现在跑之前就会把环境定下来，并且在第一行告诉你。

## 四、结果怎么看：三个词

| 你看到的 | 意思是 | 你要做什么 |
|---|---|---|
| **通过 (passed)** | 页面显示符合预期 | 不用管 |
| **失败 (failed)** | 页面显示**不符合**预期，或者操作点不上 | 看报告里的失败步骤 + 截图，拿去提 Bug |
| **跳过 (skipped)** | 这次不适合测（比如答题活动今天没上线） | 一般不用管，但**数量突然变多要当回事** |

> 为什么「跳过」要留意：它不算通过。如果哪天原本能跑的用例全变成跳过，
> 说明环境变了（活动下线、改版、小程序没打开），而不是「一切正常」。

### 报告里每一行都写了什么

打开网页报告，点开任意一条用例，你能看到：

- 用例名字 —— **都是中文**：表格用例用你填的「用例编号 + 用例标题」，
  代码写的用例也有各自的中文名（文件名本身是英文，那是给写代码的人看的）；
- 每一步叫什么、花了多少秒；
- 失败那一步的**报错原文**和**当时的截图**；
- 「用例上下文」：用例中途记下来的信息（例如「刚点的那个专栏叫什么」）。

同一台电脑上，截图还都在 `report/photo_app/` 里按用例分目录存着，
表格用例的截图在 `report/photo_app/表格用例/用例编号/` 下面。

## 五、加自己的用例（不写代码）：填一张表

这是这套框架给零基础用法准备的路子：**在 Excel 里一行一行写「做什么」，剩下的交给框架**。

### 表在哪

`cases/用例表.xlsx`。里面有四张工作表：

1. **用例** —— 你要填的就是这张；
2. **动作清单** —— 能写哪些动作、每个动作要什么参数（**按用途分了 6 类**，找起来像翻目录；
   每个动作后面写着「会不会改数据」）；
3. **名称候选** —— 那几个要填**数据里的名字**的参数（课程名 / 案例名 / 活动名）的候选值，
   **可以直接复制粘贴**，不用去猜、也不用记（它由 `python tools/export_cases.py --dropdown` 刷新；
   里头还标着课程"我们账号买没买、有几节课时"，挑样本时用得上）；
4. **填写说明** —— 一页纸的填表规则。

### 表长什么样：8 列，分两种（2026/10/14 起）

| 哪几列 | 列名 | 谁填 |
|---|---|---|
| **按用例**（表里纵向并成一格，只写在第一条步骤行上） | 用例编号 / 用例标题 / 前置条件 / 备注 | 一条用例填一次 |
| **按步骤**（每一行都要填） | 步骤序号 / 动作 / 参数1 / 参数2 | 每一步填一次 |

编号写法：`ZW_` + 三位数字（`ZW_001`、`ZW_002`…）。**整表统一用这个格式**，现在 27 条用的是
`ZW_001`~`ZW_028` 里的号（中间空的 `ZW_022` 是删掉的调试用例留下的 —— **空号不用管**，
编号只要「唯一」就行，不要求连续）。你自己新加就挑一个没用过的号。

### 怎么填（记住五条就够）

1. **一行 = 一个步骤**。同一个「用例编号」的若干行合起来是一条用例，按「步骤序号」顺序执行；
2. **一案一块**：一条用例的「用例编号 / 用例标题 / 前置条件 / 备注」在表里是**并起来的四格**
   （只写在第一条步骤行上），看上去就是一块一块的，一眼数得出几条用例、每条几步。
   所以每行都要填的只有 **步骤序号 + 动作**（+ 该动作要的参数）几列；
3. **「前置条件」写"跑这条之前手机/数据得是什么状态"**（要不要先登录、首页得有什么卡、
   库里得有什么数据）。它不会被自动执行，是给人看的 —— 也是"这条挂了先查什么"的线索，
   还会贴进测试报告里（别人看报告时不用回来翻 Excel）；
4. **「备注」是整条用例的备注**（也并成一格）。想单独说明某一步，就写在同一格里，
   用「第2步：…」开头；写缺陷/需求编号也写这里（以后回头查"这条为什么在测"很方便）；
5. **动作只能填「动作清单」里的名字**，而且那一列是**下拉框**（点单元格右边的小箭头直接选）——
   打错的字根本选不出来，少一轮报错；填了别的也会在导出时当场报错（不会默默跳过那一行）。
   **参数不用就留空**；该用没填、或者不该用却填了，也会报错 —— 这是故意的，防止手滑填错列。
   **不知道参数该填什么，就看「动作清单」的「怎么填（示例）」那一列，照抄即可**
   （有两个参数的写成 `参数1 / 参数2`，例如 `滑动` 的示例是 `3 / 上`）。

> 自己新加的行不会自动并格。想让它并回去、顺便刷新下拉框（加了新动作之后也要刷），跑一次：
>
> ```powershell
> python tools/export_cases.py --dropdown
> ```
>
> 它**只动排版和下拉框，不动你填的内容**。表格正开着 Excel/WPS 时会存不进去，先关掉再跑。

### 填完怎么跑

```powershell
python run.py                 # 会先自动把表格导出，再把表里的用例跑一遍
python run.py -k ZW_002    # 只跑表格里的这一条
```

> 「导出」你不需要手动做，`python run.py` 会自动做。
> 表格有问题时会**当场停下来并告诉你第几行错了** —— 因为如果继续跑，
> 跑的就是上一次的表格，那种「通过」是假的。
>
> 另外导出时还会给你几条**建议**（不拦你，只提示），比如「这条用例一个检查都没有，
> 测不出问题」「第一步不是回到首页，起点会被上一条带脏」「最后一步会停在二级页，
> 建议补一步回到首页」—— 都是别人踩过的坑，照着改就行。

### 写用例时最常用的动作（调试工具箱）

59 个动作里，**写用例和调用例时真正天天用的是下面这几个** —— 先把它们用熟，再慢慢扩展到其余动作。

**必会的 5 个**

| 动作 | 什么时候用 | 怎么用 |
|---|---|---|
| `回到首页` | 每条用例**第一步**；调用例时想"把现场归零"也单独跑它 | 不用参数 |
| `打印页面文字` | **不知道断言该填什么字的时候** | 加一行跑一次，日志里会出现"当前屏幕上的文字"（前 600 字），照抄屏幕上的字填进「检查文字显示」 |
| `检查文字显示` | 最常用的验收断言（会反复重试，默认最多等 8 秒） | 参数1 填屏幕上看得见的那段字，**一字不差** |
| `检查元素存在` | 最轻的确认：先搞清楚"这个东西找不找得到" | 参数1 填选择器（例如 `.search-container`）—— 选择器从哪来？看下面「看结构」 |
| `滑动` | 目标在屏幕外（列表要滑到底才看得到） | 参数1 选方向（上/下，**留空 = 上**）；**它自己一直滑到不动为止**，不用填次数（见下面「滑动 = 滑到底」） |

**看情况用的 5 个**

| 动作 | 什么时候用 |
|---|---|
| `打开…` 系列（`打开搜索页` / `打开案例库` / `打开课程详情` / `打开学习中心专栏`…） | 走到要测的那一页。**有专用动作就别用「点文字」**：专用动作会"确认真的到了"，点文字只是点一下 |
| `点文字` / `点选择器` | 探索"点了会到哪"的兜底手段；文案有重名时用 `点选择器` 更准 |
| `检查文字不显示` | 反向断言（例：零结果时才出现的提示，有结果时**不该**出现） |
| `检查元素数量` | 要数个数（例：热门话题正好 5 条） |
| `返回上一页` | 探索时从二级页退回上一级。**收尾还是用 `回到首页`**，它能把滚动位置和筛选 tab 一起归位 |
| `下拉刷新` | **后台改了数据、想让小程序立刻看到**时用（例：把一条帖子置顶、把某个活动开关关掉）。它会自己确认"刷新真的发生了"，没触发会重试并报错 —— 实测后台置顶后下拉一次，约 1 秒第一条就变「置顶」。注意搜索页/帖子详情这类二级页没有下拉刷新（要刷新就返回上一页重进） |
| `等待` | 兜底，**尽量别用**：先看有没有对应的「检查…」动作（断言自带等待，比死等稳） |

**三个不是动作、但同样重要的调试手段**

```powershell
python run.py -k 用例名里的几个字      # ① 单条复跑：调试的主循环（改一行、跑一条、看结果）
$env:UITEST_DEBUG = "1"               # ② 打开框架内部日志（前台页判定、每步耗时）；看完 Remove-Item Env:\UITEST_DEBUG
```

③ **看页面结构**（想知道某个东西的选择器/class 时）—— 两种用法，挑一个顺手的：

```text
# 用法一：表格动作（和别的动作一样，写一行就跑）
打印页面结构     只看有文字      ← 参数1 下拉选「全量」或「只看有文字」
```

```powershell
# 用法二：命令行脚本（不用动表格，临时看一眼最方便）
node test_case/diagnostic/dump_page.js --only-text     # 只看有文字的分支（推荐）
node test_case/diagnostic/dump_page.js --tag wx-text   # 只看某一类元素
```

两种用法产物一样：控制台只打前 300 行（免得刷屏），**完整内容写到 `report/dump_<月日_时分秒>.txt`**，
可以在编辑器里搜。挑「检查元素存在」要填的选择器（例如 `.search-container`）就从这里看。

#### 「滑动」= 一直滑到不动（滑到底 / 滑到顶）——2026/10/14 定稿

**不用你算滑几次、也不用管一次滑多少**：写一行，它自己一滑一滑地滑，直到页面不再移动为止。

```text
2  滑动    上        ← 往下翻到底（最常用；参数1 留空也是「上」）
2  滑动    下        ← 一路滚回顶部
2  滑动    上    5   ← 想限制次数才填参数2：最多滑 5 次（安全上限）
```

- 参数1 = **方向**：`上`（往下翻到底）/ `下`（滚回顶部），**可不填**，留空 = 上；
- 参数2 = **最多滑几次**（1~50），**可不填**，留空 = 10；
- 滑到不动就停，日志会写"已滑动 N 次，页面不再移动（到底了）"；
- **滑满上限还在动不当失败**，但会明确打一句"还能继续滚"——首页那种**无限加载**的列表就是滑不到头的，
  这句就是提示（下一步要是找不到目标，把上限调大或先确认目标在不在这一页）。

实测（这台设备，案例库列表，56 个案例）：

| 干什么 | 结果 |
|---|---|
| `上`（滑到底） | 滑 **6 次**到底；到底之后再滑一次**页面不动**（判定可信） |
| `下`（滑回顶部） | 滑 **5 次**回到 scrollTop 0 |
| `上` 但把上限写成 1 | 如实报"还能继续滚"（**不会假装到底**） |

> 旧写法（`滑动 \| 3 \| 上`，参数1 填次数）**已经不支持**：导出时会直接报错并告诉你"次数搬到参数2了"。

#### 「选择器」到底怎么写（三种写法覆盖绝大多数情况）

选择器 = **给框架的"查找条件"**。它不是自己起的名字，而是把页面元素的 **class（或标签）照抄下来**。
清空了一个概念之后，就只剩三种写法：

| 写法 | 意思 | 真实例子（从 dump 里抄的） |
|---|---|---|
| `.abc` | **class 等于 abc** 的元素（点号 = "class 是"） | `<wx-view class="search-container">` → 选择器写 **`.search-container`**（首页搜索栏） |
| `标签.abc` | 必须是**这种标签**且 class 是 abc（比上面更准，避免别的元素也叫这个 class） | `<wx-input class="h5-input search-input">` → 写 **`wx-input.search-input`**（搜索页的输入框） |
| `甲 乙`（**中间空格**） | **甲"里面"的乙** —— 空格不是"和"，是"后代/包含" | `<wx-view class="hot-topics …">` 里面那些 `<wx-view class="inline-flex …">` → 写 **`.hot-topics .inline-flex`**（热门话题的 5 个条目） |

还有两个偶尔用到的：结尾 `-active` 通常表示"**选中的那个**"（例如 `.nut-tabs-titles-item-active`）；
`[class*="abc"]` 表示"class 里**包含** abc"（Taro 的类名带随机后缀时用它，框架内部就用了
`[class*="custom-tab-bar"]` 判断底部 tab 栏）。

**「怎么知道该填哪个」的完整动作**：

```text
1  打开搜索页
2  打印页面结构        只看有文字      ← 跑一次
```

去 `report/dump_*.txt` 里搜你要找的东西（比如搜「搜索」），找到它那一行，
把 `class="…"` 里的名字**抄下来、前面加个点**，就是选择器。

> **大多数时候你根本不需要选择器**：能按文字断言的就用「检查文字显示」。
> 只有两种情况才轮到它 —— ① **没有文字可打**（图标按钮、容器、卡片）；② **文字重名**
> （屏幕上两处都是同样的字，按文字点只会点第 1 个）。
>
> 另外两条要知道的：选择器**命中多个时框架取第 1 个**（所以写得越具体越好）；
> 它是"页面现在的样子"，小程序改版后可能失效 —— 用例红了、报"命中 0 个"时，
> 重新 `打印页面结构` 抄一遍新的就行。

#### ⚠️ 最容易犯的那个错：把元素的多个 class 抄成了一串

页面上一个元素常常挂着**好几个 class**，例如搜索栏那行字就是：

```html
<wx-text class="fs-28 text-blacks28 ml-2">搜索...</wx-text>
```

很多人会**整串照抄**成选择器 `.fs-28 text-blacks28 ml-2` —— 这就错了：CSS 里**空格是「里面的」**，
那句话于是变成"找 `.fs-28` 里面的 `<text-blacks28>` 里面的 `<ml-2>`"，必然一个都找不到。

**同一个元素上的多个 class 要连着写、不加空格**：`.fs-28.text-blacks28.ml-2`；
或者更省事：**只留最有辨识度的那一个**（`.fs-28`）。

> 好消息：框架现在**会自己提醒**你。填错成这种串、又找不到时，报错里会直接给出正确写法并附上
> "实测能命中几个"，例如：
>
> ```text
>   [提示] CSS 里空格表示「里面的」（后代），不是「同时满足」。
>     你填的这串看起来是同一个元素上的多个 class —— 那样要连着写、不加空格：
>     .fs-28.text-blacks28.ml-2（实测能命中 1 个，可以直接照抄）
>     也可以只留最有辨识度的那一个，例如 .fs-28。
> ```

#### 那 **id** 呢？——**不能用**（2026/10/14 删掉了 id 定位）

每个元素身上除了 class 还有 **id**（形如 `id="_AQ"`，Taro 自动生成的）。它看着最精确，
但**它不稳定，所以框架里不留这条路**：当天加的三个动作（`点id` / `检查id存在` / `检查id不存在`）
当天就删掉了，现在往「点选择器」「检查元素…」里填 `#_AQ` / `[id="_AQ"]` 也会**在导出时直接报错**。

为什么删？实测（2026/10/14）：

| 场景 | 结果 |
|---|---|
| 同一个页面一直开着（首页那种） | ✅ id 不变（搜索栏 `_AQ` 隔了一天还在） |
| **重进一次同一个页面**（退出去再进来） | ❌ **全变**：搜索框 `_JN`→`_Kr`，5 个热门话题的 id 也全换了 |
| 换一天再看（新开的页面） | ❌ 变（搜索页输入框昨天 `_RlY`、今天 `_Hj`） |

原因：id 是"**这一次页面实例**"的产物，页面重建一次就重新分配一遍。
按它写的用例会**今天绿、明天红**（而且红得莫名其妙）—— 那种用例比没有更坏。

**那用什么定位？按可靠程度来（记住这个顺序就够了）：**

| 优先级 | 用什么 | 动作 |
|---|---|---|
| ① 最稳 | 页面上**看得见的文字** | `点文字` / `检查文字显示` / `检查文字不显示` |
| ② 其次 | **业务 class**（源码里手写的那种，例如 `.search-container` / `.eco-tab-bar-container`；怎么找见下面「挑 class 只挑业务类名」） | `点选择器` / `检查元素存在` / `检查元素数量` |
| ③ 最后 | **结构写法**（例如 `.hot-topics .inline-flex`，配参数2「第几个」） | `点选择器` |

> `打印页面结构` 的输出里**仍然会显示 id** —— 那是给你看"元素长什么样、谁包着谁"用的，
> 不是让你抄出来当锚点的。

#### 挑 class 只挑"业务类名"（2026/10/16 起有源码可查）

页面上一个元素的 class 往往是一长串，例如 `fs-28 text-_h3D3D3D_ whitespace-nowrap overflow-hidden`。
**这一串里能当锚点的通常一个都没有** —— 它们叫**原子类**（样式系统编译出来的样式名），
一屏上到处都是、换个设计稿就变。

能当锚点的是**业务类名**：源码里手写的那种，例如 `eco-tab-item`、`case-list-card`、`overlay-mask`。
它**看得懂**、而且在运行时 DOM 里原样保留（实测 `.eco-tab-item` 命中 4 个 = 4 个 tab）。

分不清哪个是哪个没关系，用工具查（**不用自己翻源码**）：

```powershell
python tools/scan_anchors.py --find case      # 按关键词找类名，前面加个点就能填进表格
python tools/scan_anchors.py --module qa      # 看"有问必答首页"这个模块里都有哪些类名
```

查出来的名字直接抄（前面加个点）：`case-list-card` → 填 `.case-list-card`。
完整对照（我们已经用上的锚点 + 源码出处）见 `knowledge/前端源码与选择器对照.md`。

#### 命中了多个，怎么挑其中一个：**参数2 填「第几个」**

这是最常见的定位难题：热门话题那 5 条标题 class 完全一样（`.fs-28 text-_h3D3D3D_ …`），
`点选择器 .fs-28` 会命中 5 个，而框架默认只取第 1 个。**不用去学复杂语法** ——
「点文字」和「点选择器」的**参数2 就是「第几个」**，留空 = 第 1 个（老用例完全不受影响）：

```text
3  点选择器    .hot-topics .inline-flex    2      ← 点第 2 条（实测：匹配 5 个，取第 2 个）
```

日志里会写明它取了第几个（`匹配 5 个，取第 2 个`），取不到那么多会直接报错（不会静默退回第 1 个）。

**但"第几个"有个坑：它按 DOM 顺序数，而你可能根本不知道有几处。** 实测（2026/10/16，首页）：
`推荐` 这俩字**整页命中 2 处** —— 一处是筛选 tab，另一处是信息流里某张卡片的标题。
谁在第 1 个是**数据凑巧**决定的，换个排序就可能点到卡片上，而且**点错了不报错**。

这种时候用 **`范围内点文字`**：**先圈定范围，再在里面找文字**（参数1 = 范围、参数2 = 文字）。

```text
3  范围内点文字   .eco-tab-bar-container    推荐     ← 实测：整页 2 处 → 圈进筛选栏只剩 1 处
```

顺带一个好处：命中多处时，日志会把**每个候选**打出来（标签、class、坐标、前 20 字），
并标出实际点了哪一个 —— "点错了地方"从此在报告里看得见。

想用**断言**挑其中一个时，选择器本身也能表达"第几个"（这几种都实测过，各命中 1 个）：

| 挑法 | 写法（填进「检查元素存在」等） |
|---|---|
| 按文字 | `.fs-28:has-text("压铸圈")` |
| 按位置 | `.hot-topics :nth-match(.fs-28, 2)` |
| 按父容器的第几个 | `.hot-topics .inline-flex:nth-child(2) .fs-28` |
| 按"同类型第几个" | `.hot-topics wx-view:nth-of-type(2) .fs-28` |

#### 定位方式怎么选（从省事到费劲，按这个顺序试）

| 顺序 | 用什么 | 什么时候 |
|---|---|---|
| 1 | **专用动作**（`打开搜索页` / `打开案例库` / `检查首页筛选栏顺序`…） | 首选。它们内部已经写好了最稳的定位，还会"确认真的到了" |
| 2 | **文字**（`点文字` / `检查文字显示`） | 屏幕上那段字**唯一**时最好用；文字改了要跟着改 |
| 3 | **文字 + 第几个**（`点文字` 参数2） | 文字重名时 |
| 4 | **class**（`.abc`，必要时用容器收窄：`容器 .abc`） | 没有文字可打（图标按钮、容器）；class 重复就再加"第几个" |
| 5 | **结构位置**（`:nth-child` / `:nth-of-type`） | 上面都不行时。改版后最容易坏 |
| ❌ | **id** | **不要用**：重进一次页面就全变（实测） |

### 一条新用例的调试顺序（照着走）

1. **先在手机上手动点一遍** —— 确认这条路走得通，并记下屏幕上出现的关键文字；
2. 在表里写骨架：`回到首页` → `打开…` → `检查…` → `回到首页`；
3. `python run.py -k 新用例名` 跑一次；
4. 红了 → 打开报告看**失败那一步的截图**，先分清楚"是我写错了"还是"产品真的不对"；
5. 断言不知道填什么 → 加一行 `打印页面文字`，跑一次，照抄屏幕上的字；
6. 元素找不到 / 卡片数不对 → 用 `滑动` 把目标滚进屏幕，或者看上面的「看页面结构」；
7. 绿了以后**先让它红一次**：把期望值故意改错，确认它真的会失败，再改回来（不做这一步，你不知道它是真绿还是假绿）；
8. 改回绿，收工前跑一遍 `python scripts/verify-all.py`。

> 想练"该红时会红"，用只读用例改错文字就够了。

## 六、表格填错了，你会看到什么

框架不会笼统地说「你错了」，而是指到行：

```text
用例表有问题（2 处），没有导出：cases/用例表.xlsx
· 第 5 行：不认识动作「打开首贝」。可用的动作（共 48 个）：回到首页、切到用户中心、…
  · 第 7 行：动作「打开搜索并输入」的「参数1」要填「关键词」，现在是空的
```

常见几类对照：

| 报错里出现 | 意思是 | 怎么改 |
|---|---|---|
| 不认识动作「xxx」 | 动作列写了清单里没有的名字（多半是错别字） | 按「动作清单」工作表改 |
| 参数1 / 参数2 要填… | 这个动作需要参数，你留空了 | 补上 |
| 用不到「参数1」 | 参数填多了（常常是把参数填到了备注列旁边） | 清空多余的那列 |
| 步骤序号只能填… | 写了「一」「1.5」这种 | 改成 1、2、3… |
| 有的步骤写了顺序号、有的没写 | 同一条用例里混着写 | 要么全写，要么全不写 |
| 「用例标题」已经是…这里又写成… | 同一条用例的两行写了两个不同的标题 | 标题只写一次（表里它是并起来的一格） |
| 「备注」/「前置条件」已经是… | 同一条用例的两行写了两个不同的备注（或前置条件） | 同一条用例只有一份备注：把两句话写进同一格，用「第3步：…」分开 |
| 这条用例没写「用例标题」 | B 列空着（标题是必填的） | 补一个中文标题 |
| 用例表有问题…已停止本次运行 | 表格有错，故意不跑 | 改完再跑；只想跑别的用例就点名文件，如 `python run.py suprecast_app/test_example.js` |

## 七、「提交」这类按钮：默认不让点，要测就得开开关

因为我们用的是**真实账号、真实数据**（这个测试环境没有独立的测试账号）。
点一下「提交答卷」就真的用掉一次机会、真的写进数据库 —— 不是演练。

所以默认有两道防线：

1. 表格里的「点文字」有安全阀：**提交、兑换、签到、下单、支付、购买、
   领取、抽奖、报名、删除、退出登录、退款、取消订单** 这些字一律点不了，会直接报错拦下来。
2. 「打开答题活动」只打开页面：不选选项、不提交。

### 想测「提交答卷」怎么办（2026/10/12 起可以了）

你在 10/12 同意了两件事：**可以在测试库里删我们自己的答题记录**、**要测写链路**。
于是现在有这么一条完整链路 —— 而且跑前跑后都会自动把记录清干净，所以可以反复跑：

```text
用例编号 ZW_104 | 用例标题 答题提交后变成已参加
  1  回到首页
  2  打开答题活动
  3  复位答题记录        Z-B4-答题角标     （这次活动叫什么，第 2 步跑完的日志里能看到）
  4  逐题作答
  5  检查文字显示        已答
  6  提交答卷
  7  检查文字显示        已参加本次活动
  8  检查答题记录数      Z-B4-答题角标 / 1  （界面上说成功，库里也得真有这一条）
  9  复位答题记录        Z-B4-答题角标
 10  回到首页
```

**必须多敲一句开关**，不然第 3、6、9 步会直接报错（报错里会告诉你这句话怎么写）：

```powershell
$env:UITEST_ALLOW_SUBMIT="1"      # 打开"允许写数据"的开关（只对当前这个窗口有效）
python run.py -k ZW_104        # 然后正常跑
```

不想写了、直接用现成的：`$env:UITEST_ALLOW_SUBMIT="1"; python run.py -k 答题写链路`
（对应文件 `test_case/suprecast_app/test_quiz_submit.js`）。

**案例复制**也是同一条路子（2026/10/12 加）：需求 713381608 要求「复制完成后弹出提示
『复制成功 / 使用手机号登录智铸超云，即可查看案例详情』」—— 复制一次会写库，
所以同样要开开关：

```powershell
$env:UITEST_ALLOW_SUBMIT="1"; python run.py -k 案例复制写链路
```

它会：记下"复制前的数字"（水位）→ 打开案例库第一张案例 → 点「复制案例」→
断言那句提示逐字出现 → 读数据库确认**复制记录 +1、复制数 +1** → **自动复位**
（删掉这次那条记录、把复制数改回去）。万一中途失败，收尾也会复位。

**表格里也能写复制用例**（2026/10/12 加）：动作列选「**复制当前案例**」，
它自己就是一条龙（含自动复位），你只要在它前面加两步把页面走到详情页即可。
表格里已经放了一条现成的模板 `ZW_016`，照抄就行：

```text
用例编号 ZW_016 | 用例标题 案例复制：点复制后弹出「复制成功 / 使用手机号登录智铸超云」
  1  回到首页
  2  打开案例库
  3  打开第一个案例
  4  复制当前案例
  5  检查文字显示        复制成功
  6  回到首页
```

没打开开关跑它时，第 4 步会记成**跳过**（报告里写明"「复制当前案例」会写真实数据，
但这次没有打开开关"）—— 跳过**不等于**通过，摘要里也会单独列出来。

> **付费案例**（例如 `ZW_019` 用的「填充任务1」，5 积分）走的是同一条路，只是中间多一步：
> 点「复制案例」会先弹一个确认框「确认复制案例？花费积分：5 / 兑换成功后，不支持撤回兑换」，
> 点「确定」才会真的复制。**这一步会扣积分，而且扣掉的积分不复位**（积分记在中台，
> 本仓的工具够不到）—— owner 2026/10/12 已同意接受这个代价。记录与复制数照常会自动复位。

三条注意：

- **活动名要一字不差**。「答题」卡背后的活动会换人（有时是「Z-B4-答题角标」，有时是
  「Z-题干图验证」），名字对不上时工具会**拒绝执行**，不会清错活动。
- **只写测试环境**。库名不像测试库时，复位工具会拒绝干活。
- 别的写操作（积分兑换、签到、下单）**还没有**复位手段，所以还测不了 —— 要用得先做清理工具。

## 九、常见问题（照着对号入座）

### 报错里有 `unrecognized arguments: --alluredir`

你用的 Python 环境里少装了一个插件。**在哪个环境跑，就在哪个环境装**：

```powershell
pip install -r requirements.txt
```

如果你是自己建过虚拟环境（目录名像 `.venv`）并激活了它，那套环境是独立的一份，
也得装一次；或者敲 `deactivate` 退出它，改用系统 Python 跑。

### 报错说 `找不到前台小程序webview`

手机上没有打开小程序。按第三节第 1 步把微信里的小程序点开，再跑一次。

### 一条用例都没跑（`collected 0 items`）

多半是在错误的目录下执行了 pytest。**用 `python run.py` 就不会有这个问题** ——
它自己会切到正确目录（必须切的那一步已经写进代码了）。

### `adb devices` 看不到手机

依次检查：手机上「开发者选项 - USB 调试」开了没；数据线是不是只能充电的那种；
手机上有没有弹「允许调试」的对话框。

> 2026/10/12 起：**手机没插好时 `python run.py` 会当场停下并告诉你上面这三步**，
> 不会再"跑十几分钟、报 20 多条失败"（那种报告里真正的原因只有一句，很容易被埋掉）。
> 退出码是 2（"运行被中断"），不是"用例失败"。
> 只想收集用例、不跑真机时用：`python run.py --collect-only`（这个不需要手机）。

### 提示「检测到多台设备」

那就明确指定用哪台：

```powershell
python run.py                                        # 先看报错里列出的序列号
$env:UITEST_DEVICE_SERIAL = "3B1F64EA9BBUTE00"       # 再指定用哪台（只对当前这个窗口生效）
python run.py                                        # 同一窗口里再跑
```

> 别写成 `set UITEST_DEVICE_SERIAL=...` —— 那是 cmd 的写法，在 PowerShell 里
> **不报错、但也不生效**（这类「看起来成功了其实没生效」是这套框架最防备的事）。

### 跑到一半，手机界面被别的东西抢走了

这台手机**同一时间只能有一个人跑测试**：另一个 AI、另一个窗口、或者你自己在用手机，
都会互相打断（表现是"点击了但没反应"、页面停在奇怪的地方）。
跑之前先确认没有别人在跑。

### 一次全量跑里有 1 条红了，单独跑它却过了

先别急着改代码 —— 这多半是**偶发**，不是功能坏了。已知的两类原因：

- `adb` 点击偶尔点到旁边的元素（日志里会出现「向上第 N 层找到可点击容器」这样的话）；
- 小程序同时开着好几个页面时，框架偶尔会认错「现在屏幕上显示的是哪一个」。

这两件事都写在 `docs/踩坑记录.md`（坑 15~17）里，框架也加了自愈，但**没有根除**。
遇到时的标准动作：先用 `python run.py -k 用例编号或文件` 单独复跑一次确认；
如果单独跑还是红，那就是真问题，把报错原文（连同上面几行）发出来。

### 想看框架「内部判断」的细节（调试用）

默认**不打** DEBUG —— 那些「前台页解析: 候选=5 活跃=1 元素数=423」之类的细节，一次跑能刷几百行，
会把真正该看的东西（哪条失败、为什么、截图在哪）埋掉。需要排查时开一下就行：

```powershell
$env:UITEST_DEBUG = "1"        # 打开
python run.py -k 用例编号
Remove-Item Env:\UITEST_DEBUG  # 看完记得关掉（只对当前窗口生效）
```

开了之后你能看到「框架是怎么判断当前在哪个页面的」以及每一步的耗时 ——
提 Bug 或找人帮忙时，把这些行一起贴出来最有用。

### 想知道"这一页上到底有什么文字 / 该用什么选择器"

表格里有个动作叫 **`打印页面文字`**：加一行跑一次，屏幕上看得见的文字就进日志了 ——
不知道「检查文字显示」该填哪段字时，先用它看一眼（挑完把那行删掉）。

要更细的结构（连元素、class、id 都看），可以用 `dumpElements`（写在 `.js` 用例里，
或让 AI 帮你临时加一步）。它 2026/10/13 增强过，现在：

```js
[dumpElements, null]                      // 全量：整个页面的结构
[dumpElements, { onlyText: true }]        // 只看"有文字"的分支（挑文案最省事）
[dumpElements, { tag: "wx-text" }]        // 只看某一类元素
```

- 控制台最多打 300 行（免得刷屏把要看的东西冲没），**完整内容写到 `report/dump_<月日_时分秒>.txt`**，
  可以在编辑器里搜；
- 结尾会打一行「本页元素 N 个 / 遍历 M 个 / 输出 K 行」的统计，方便判断页面是不是变了样。

### 输入中文没反应，还不报错

**先说结论：现在直接填中文就行**（2026/10/13 打通）——「打开搜索并输入」的参数里写中文，
框架自己会处理。你不需要做任何事，只需要知道它会慢 1~2 秒。

它是怎么做到的：`adb shell input text` 只认 ASCII（中文发过去不报错也不生效），所以框架遇到中文时
**临时切到手机上装的 ADBKeyboard 输入法**，用广播把中文送进去，**用完自动切回你原来的输入法**
（实测：跑完 `settings get secure default_input_method` 还是你原来那个）。现成例子：
表格里的 `ZW_024` —— 打开搜索并输入「压铸」→ 执行搜索 → 检查文字显示「压铸」，真机 5 步全绿。

> 换手机 / 重装系统后要重新装一次那个输入法（约 17KB，开源）：
> `adb install -r ADBKeyboard.apk`（APK 走 CDN 镜像下载，见 knowledge 的「中文输入」一节）。
> 没装的话，遇到中文会**明确报错并告诉你这条命令**，不会静默失败。

**另一条不依赖输入法的路**（适合不想在手机上装东西、或者 ADBKeyboard 出问题的时候）：
往搜索历史里造一个中文词，然后点它 —— 一样能触发中文搜索：

```powershell
# 1. 往测试库插一行中文搜索历史（默认只预览，要 --yes 才真写）
python tools/search_history_tool.py --user 1966910 --keyword 压铸 --add --yes
```

```text
# 2. 表格里这么写（ZW_023 就是这么写的，可以直接抄）
1  回到首页
2  打开搜索页
3  点搜索历史里的词     压铸        ← 点它就直接触发一次中文搜索
4  检查文字显示         压铸        ← 结果页搜索栏里应当是这个词（= 真的照它搜了）
5  回到首页
```

用完想撤掉那行历史：把 `--add` 换成 `--delete` 再跑一次。

> 这条路的依据（都是实测，不是猜的）：库里的 `search_history` 表就是搜索页那排「搜索历史」词条
> （我们账号 7 条和手机上 7 个词一一对应）；插一行中文 → 重新进搜索页就能看到 → 点它触发搜索。
> 另外两条路试过、**都不通**：Playwright 的 CDP `insertText`（小程序的输入框是原生组件，
> DOM 里那个 `<input>` 是 disabled 的镜像）、JS 注入（只改到"镜像属性"，提交后跟没输入一样）。

## 十、术语小抄

| 你看到/听到的词 | 人话 |
|---|---|
| 用例 | 一条测试：一段「先做这个、再检查那个」的流程 |
| 步骤 | 用例里的一小步（表格里就是一行） |
| 断言 / 检查 | 「我确信这里应该显示 X」的这句话；不成立就算失败 |
| 通过 / 失败 / 跳过 | passed / failed / skipped，见第四节 |
| pytest | 跑测试的调度器，负责收集用例、统计成绩 |
| Allure | 生成那份带图的网页报告的工具 |
| adb | 电脑和安卓手机之间的连接通道（点屏幕、截图都靠它） |
| webview / 前台页 | 手机上小程序真正显示内容的那一层；同一时刻可能有多个，得动态找出「正在显示的那个」 |
| 页面对象 | 把「某个页面长什么样、能做什么」写在一个文件里，改版时只改它 |
| 动作清单 | 表格第二张工作表：能写哪些操作 |
| 步骤日志 | 每一步做了什么、花了多久的原始记录，失败时最有用 |
