# 一页纸操作卡（贴给同事看的那种）

> 这份是给"只想跑一下、看懂结果"的人准备的。想自己写用例看
> [使用手册-零基础.md](使用手册-零基础.md)；想改框架看 [README.md](../README.md)。

## 1. 跑之前（30 秒）

```powershell
cd C:\Users\admin\Desktop\小程序自动化框架   # 进项目目录
adb devices                               # 必须看到一行 xxx  device（不是 unauthorized）
```

手机上：**微信里把小程序打开**（框架不会替你打开微信），别拔线、别锁屏。

跑起来后**第一行**会打印 `本次环境：…（appid wx…）` —— 那就是这次在测哪个小程序。
默认是测试环境；临时换：`python run.py --env prod`（生产现在会被拦下，因为 appid 没填）。

## 2. 跑

```powershell
python run.py                     # 全部用例（约 12 分钟）
python run.py -k ZW_001      # 只跑某一条（名字里含这几个字就行）
python run.py -k 专栏             # 也可以按关键词挑
```

> ⚠️ 只跑一条时 **`-k` 不能省**：`python run.py ZW_001`（不带 `-k`）会被 pytest 当成"去收集
> 名叫 ZW_001 的文件" → `collected 0 items`（退出码 4）。现在框架会拦下来并直接告诉你正确写法。

> 有一条用例默认是**跳过**的：`答题写链路`（它会真的提交答卷）。要跑它得多敲一行开关：
> `$env:UITEST_ALLOW_SUBMIT="1"`，跑完再 `Remove-Item Env:\UITEST_ALLOW_SUBMIT`。
> 跳过不等于通过 —— 它只是"这次没跑"。

## 3. 看结果（就看三处）

1. **最后一行**：`19 passed` = 全过；`1 failed` = 有失败；`skipped` = 跳过（这次环境不适合测、或者写开关没开，**不算通过**）。
2. **往上一点**：`--- 步骤明细 ---`，每条用例每一步叫什么、几秒、失败时的报错原文和**截图路径**。
3. **网页报告**：`report\allure-report\index.html`（双击打开，带截图和每一步耗时）。

## 4. 红了怎么办（三步）

```powershell
python run.py -k 用例编号          # ① 单独复跑一次（偶发 vs 真问题，先分清）
```

② 打开报告看**失败那一步的截图** —— 手机上当时是什么样，截图最可信。
③ 还是红的话，把这三样发出来：**用例编号 + 控制台里那条报错（连上面几行）+ 截图**。

## 5. 三个最常见的坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 报 `找不到前台小程序webview` | 手机上没打开小程序 | 微信里把小程序点开再跑 |
| `adb devices` 看不到设备 | USB 调试没开 / 线只能充电 | 手机上开「USB 调试」，换根数据线。**（手机没连好时 `python run.py` 会当场停下并提示这三步，不会跑十几分钟才报一堆失败）** |
| 报「找不到底部 tab」 | 上一条用例把手机停在二级页 | 一般重跑就好；要稳定就在用例首尾各写一步「回到首页」 |

## 6. 想看更细的日志（排查用）

```powershell
$env:UITEST_DEBUG = "1"           # 打开（只对当前窗口生效）
python run.py -k 用例编号
Remove-Item Env:\UITEST_DEBUG     # 看完关掉
```

## 7. 记住两件事

- **这台手机同一时间只能一个人跑**（你、别的 AI、别人都不行），跑之前确认没人在用；
- **别在手机上手动点**正在跑的用例 —— 会互相打断，报错看起来会很奇怪。
