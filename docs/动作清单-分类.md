## ⑥ 答题 / 写链路（要开开关，跑完必须复位）

**会改真实数据**的动作。开关是环境变量 `UITEST_ALLOW_SUBMIT=1`；不带开关时：写动作要么报错、要么记「跳过」并写明原因（绝不假装通过）

| 动作 | 参数1 | 参数2 | 干什么 | 会不会改数据 |
|---|---|---|---|---|
| 打开答题活动 |  |  | 打开「答题赢积分」活动页（只读：不选选项、不提交） | 不会 |
| 逐题作答 |  |  | 把答题页上每道题都选上第一个选项（多题活动会一题一题点过去，屏幕外的题会自动滚进可视区）。只改前端选中态、**不写库**，所以不需要开关；但选完不提交的话，离开页面就没了（需求原文：未提交已选的选项不会保存） | 只改前端选中态（不写库、不需要开关） |
| 提交答卷 |  |  | 点答题页的提交按钮 —— **会真的写数据**。必须打开开关 UITEST_ALLOW_SUBMIT=1，否则这一步直接报错（不跳过、不静默）。跑完记得用「复位答题记录」把数据清掉 | **会写库**（必须开开关） |
| 复位答题记录 | 活动名 |  | 删掉这个活动在测试库里留下的答题记录（提交 + 明细），让「答题机会」回到能用状态。⚠️ 这是护栏动作：**默认只预览、不删**，真删要打开开关 UITEST_ALLOW_SUBMIT=1；活动名要跟页面上的标题一字不差（例如 Z-B4-答题角标）；名字找不到或有重名会被拒绝执行 | **会删库**（默认只预览；真删要开开关） |
| 检查答题记录数 | 活动名 | 期望条数 | 读数据库，断言这个活动的**提交记录**正好是 N 条（例如提交前填 0、提交后填 1）。用来把「界面上说提交成功」和「库里真有这条」对上 —— 只读，不需要开关 | 不会 |
| 复制当前案例 |  |  | 在案例详情页点「复制案例」—— **一条龙**：记下水位 → 点复制 → 断言提示「复制成功 / 使用手机号登录智铸超云，即可查看案例详情」逐字出现 → 读数据库确认复制记录 +1、复制数 +1 → **自动复位**（删掉这次那条记录、把复制数改回去）。⚠️ 会写测试库数据：必须打开开关 UITEST_ALLOW_SUBMIT=1，否则这一步记「跳过」（并说明原因）。先用「打开案例库」+「打开第一个案例」走到详情页再用它 | **会写库**（要开开关；没开时记跳过） |

## 想加一个新动作

加动作不是只在表格里写一行就行 —— 表格里能填的动作是**白名单**，要按这套顺序加：

1. 在 `app_sub_function/suprecast_app/` 的页面对象里写函数（别忘了 `return page`、异常要往上抛）；
2. 在 `tools/export_cases.py` 的 `ACTIONS` 里加一条（中文名字、`p1`/`p2` 写参数名、
   `desc` 说清干什么；会改数据的加 `risk`）；
3. 在 `test_case/suprecast_app/test_from_table.js` 的 `HANDLERS` 里实现同名处理函数；
4. 跑这两条：

   ```powershell
   python tools/build_actions_doc.py     # 刷新本文档（新动作必须归到某一类，否则报错）
   python scripts/verify-all.py          # 离线闸门（动作↔实现、文档数字、本文档是否最新…）
   ```

新的动作名没出现在 `GROUPS` 里会直接报错 —— 这是故意的，防止它悄悄漏在清单外没人看。
