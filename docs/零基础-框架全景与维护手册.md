## 一、一分钟看懂：这套框架由哪几块组成

一句话：**你在 Excel 里写"做什么"，框架把它翻译成对手机上小程序的点击与检查，最后给你一份带截图的中文报告。**

```text
   你：在 Excel 里一行写一个步骤
        cases/用例表.xlsx
              │
              │  python run.py  （开跑前自动做三件事：
              │   ① 导出成 json ② 检查表有没有填错 ③ 看手机连没连、小程序在不在前台）
              ▼
        cases/用例表.json  ──►  test_case/（pytest 收集成一条条用例）
                                      │
                                      │  每一步 = 一个「动作」
                                      ▼
                        ┌─────────────┴──────────────┐
                        ▼                            ▼
              页面对象（点/滑/读页面）        数据库工具（可选，读写测试库）
              app_sub_function/…/pages/      tools/*.py
                        │
                        ▼
                 adb ──► 手机上的微信小程序
                        │
                        ▼
        report/  （每一步的截图 + 中文摘要 + 网页报告）
```

| 块 | 干什么 | 在哪 |
|---|---|---|
| **用例表** | 你唯一需要直接编辑的东西（一行 = 一个步骤） | `cases/用例表.xlsx` |
| **用例驱动** | 把表读成用例、一步步执行、记录每一步 | `test_case/suprecast_app/` |
| **动作** | 表格能填的"动词"（48 个）。每个动作在代码里有一份实现 | 清单见 [动作清单-分类.md](动作清单-分类.md) |
| **页面对象** | 真正操作小程序的那一层（找元素、点、滑、读文字） | `app_sub_function/suprecast_app/pages/` |
| **数据库工具** | 需要跟测试库对账/造数/复位时才用（不是每条用例都需要） | `tools/` |
| **闸门与文档** | 防止"报告说谎"：改动后自动检查，文档不许和代码对不上 | `scripts/verify-all.py`、`docs/` |

> 为什么要有"闸门"这一块：这套框架最怕的不是报错，而是**看起来通过了、其实没测到**
> （比如表格填错了却照旧跑上一次的表格、动作名写错被静默跳过）。所以每一处"坏了也不报错"的
> 地方，都配了一条自动检查。

## 二、家底速查（现在有多少东西）

| 东西 | 现在有多少 | 在哪看 |
|---|---|---|
| 表格用例 | **20 条 / 112 个步骤** | `cases/用例表.xlsx` |

**看一次全量跑要多久**：约 17~18 分钟（27 条用例）。单条复跑通常 20 秒~1 分钟。

## 三、日常使用：跑、看、红了怎么办

### 三条最常用的命令

```powershell
python run.py                   # 全部用例（先看手机连没连、小程序在不在前台）
python run.py -k ZW_001    # 只跑一条（名字里含这几个字就行）
python run.py --env prod        # 这一次改用"生产"环境跑（现在会被拦下，见第七节）
```

### 跑之前 30 秒自检

1. 手机连着、`adb devices` 能看到一行 `xxx device`；
2. 手机上**微信里的小程序开着**（框架不会替你打开微信）；
3. 这台手机**现在没别人在用**（同一时间只能一个人跑）。

### 看结果就看三处

1. **控制台最后几行**：`24 passed, 0 failed, 4 skipped` —— `skipped` 是"这次没测"，**不等于通过**；
2. **中文摘要**：`report/结果摘要.md`（跳过的会写明原因）；
3. **网页报告**：`report/allure-report/index.html`（每一步的截图都在里面）。

### 红了怎么办

```powershell
python run.py -k 用例编号        # ① 先单独复跑一次（分清"偶发"还是"真问题"）
```

② 打开报告看**失败那一步的截图**（手机上当时什么样，截图最可信）；
③ 还是红：把 **用例编号 + 报错原文（连上面几行）+ 截图** 一起发出来，别自己猜。

## 四、动作怎么用：6 类 + 一条用例的标准骨架

52 个动作按用途分 6 类（完整表格见 [动作清单-分类.md](动作清单-分类.md)）：

| 类别 | 个数 | 什么时候用 |
|---|---|---|
| ① 到达 / 导航 | 10 | 把手机摆到该在的页面上 |
| ② 搜索与内容（只读） | 8 | 打开某块内容看 |
| ③ 通用交互 | 6 | 点、滑、等；**"等待"能不用就别用** |
| ④ 通用断言 | 7 | 「检查…」类，用例靠它们才有意义 |
| ⑤ 需求专项检查 | 10 | 把某条需求的原文写成断言 |
| ⑥ 答题 / 写链路 | 6 | **会改数据**，要开开关、跑完必须复位 |

### 一条用例的标准骨架（照抄改中间）

```
回到首页                 ← 把起点摆正（几乎每条用例第一步都是它）
【打开 / 切到某页】
【操作几步】
【检查…】                 ← 至少一条检查；没有检查的用例测不出问题
回到首页                 ← 把手机交还给下一条用例
```

### 三个常用配方

| 我想测 | 动作组合 |
|---|---|
| 某个页面能看到什么 | `回到首页` → `打开…` → `检查文字显示` / `检查元素存在` |
| 搜索相关（三步写法，推荐） | `回到首页` → `打开搜索页` → `输入搜索关键词` → `执行搜索` → `检查文字显示` |
| 搜索相关（一条龙，省一行） | `回到首页` → `打开搜索并输入(关键词)` → `执行搜索` → `检查文字显示` —— 后者 = 打开搜索页 + 输入，两步合一 |
| 跟数据库对账 | `回到首页` → `打开…` → `检查…（带库对账的动作）`（这类动作会自己去读库） |

> **「检查…」是灵魂**。只有操作没有检查的用例，跑一百遍也是绿的 ——
> 它什么都没验。框架里 `test_login_and_navigation.js` 就是故意留下的这种反例。

## 五、维护：你会遇到的四类改动，每类改完要做什么

### 第 1 类：加/改用例（不写代码）—— 你会做得最多

改 `cases/用例表.xlsx` → 跑 `python run.py -k 新用例名`。

**改完必须做的一件事：先让它红一次。**
把某条检查的期望值故意写错（比如把「答对最多可赢积分」少写一个字），跑一次，确认它**真的失败**，
再把值改回去。这一步是"反向验证"——不做的话，你永远不知道这条断言是不是**写了个永远成立的条件**
（那种叫**假绿**，比红更危险）。

### 第 2 类：加一个新动作（要写代码，可以让 AI 做）

表格里能填的动作是**白名单**，加动作要四处一起改（漏一处，闸门会拦住你）：
页面对象里写函数 → `tools/export_cases.py` 的 `ACTIONS` 加一条 → 用例驱动里实现同名处理 → 生成文档。
照 [动作清单-分类.md](动作清单-分类.md) 末尾「想加一个新动作」那节做即可。

### 第 3 类：小程序改版了，用例开始红（页面结构变了）

症状：同一条用例昨天好好的，今天报"找不到 .xxx"或"命中 0 个"。
**这时候先当"真问题"查，别先说"框架不稳"**（踩坑记录里有整整一条教训）。
确认是页面改了之后，改页面对象里的选择器 —— 这一步建议找 AI，改动面比看起来大。

### 第 4 类：改文档 / 知识库

改完跑 `python scripts/verify-all.py`。文档里的路径、目录、坑号都被闸门盯着，
写错会当场报红（这是好事：**过期的文档比没有文档更坏**）。

### 第 5 类：需求更新了，想拉最新的（2026/10/14 新增）

以前是"人工从 CodeArts 导出 xlsx → 再喂给脚本"。现在**一条命令**：

```powershell
python tools/pull_requirements.py --tracker story,bug --details --kb   # 拉全量需求+缺陷，连正文一起，并重建知识库
```

它会重建 `knowledge/` 下的**工作项清单 / 迭代与模块汇总 / 需求描述汇编 / 缺陷描述汇编**，
并告诉你三件事，快照与报告落在 `report/需求拉取/`：

| 结论 | 意思 |
|---|---|
| **新增** | 新提的需求（知识库里还没有） |
| **消失** | 知识库里有、这次拉不到了（可能被删，也可能项目选错了） |
| **状态变化** | 例如「新建 → 已关闭」—— 知识库里那一列是旧的了 |

> ⚠️ 两个坑（都实测过）：
> ① **项目别选错**：同事那份 CLI（`oacli`）默认项目是「智铸超云(Saas)V3」，拉出来是 1170 条 Story、
> 和本仓知识库**零交集**；本命令已锁死「超云生态平台」这个项目。
> ② **凭据不入库**：账号密码在 `oacli/.env`（已被 gitignore），不要贴进文档或聊天。

## 六、一条命令：18 道离线闸门

```powershell
python scripts/verify-all.py      # 不需要手机，几秒钟跑完；全绿才算"可以提交"
```

| 闸门 | 管什么 |
|---|---|
| 1~2 | 所有 .js / .py 语法能过 |
| 3 | 用例能被 pytest 收集到（表坏了会在这里暴露） |
| 4 | 文档里的路径都能找到（死链） |
| 5~7 | 表格规则、答题复位护栏、案例复制复位护栏的自检 |
| 8~9 | 两条纯规则的自检（答题选项 2~6 个、0 课时课程对账） |
| 10~11 | 设备预检解析、环境档案规则（生产没 appid 不许跑、只读环境必须清掉写开关） |
| 12~13 | 文档索引不许漂移、数据/凭据安全不变式 |
| 14 | 框架自身完整性（动作↔实现、中文名、退出码兜底、README 里能照抄的代码是否还有效…） |
| 15 | 判分口径复算（多选必须集合完全一致）＋ 动作清单文档是否最新 |
| 16 | 报告里的截图附件：默认必须是"只贴失败步骤"（免得报告又肿起来）；需要每步都贴时，压缩确实变小、压完还是能打开的图 |
| 17 | 选择器没命中时的提示口径：把「多个 class 抄成一串」认出来并给正确写法，而合法的「里面的」写法不许乱改 |
| 18 | 需求拉取对账的纯逻辑：解析知识库清单、整理拉取结果、算「新增·消失·状态变化」—— 这三行是给人看的结论，不能算错 |

**什么时候跑**：改完任何东西、提交之前。**红了怎么办**：它会把"哪里不对、怎么改"直接打出来。

## 七、红线（碰了会出事的几件事）

1. **不要刷新 / 重开小程序**，除非明确知道后果 —— 测试环境可能因此没了（owner 2026/10/13 特别交代）；
2. **生产环境一概不碰**。`--env prod` 现在会被当场拦下（appid 没填），这是故意的；
3. **会写数据的用例**：必须先开开关（`$env:UITEST_ALLOW_SUBMIT="1"`），而且**跑完会自动复位**；
   没有复位手段的写操作（积分兑换、签到）目前**不做**；
4. **同一台手机同一时间只能一个人跑**（你、别人、别的 AI 都不行）；
5. **别在手机上手动点**正在跑的用例 —— 会互相打断，报错看起来很怪；
6. **凭据不进仓库**（`config/db.local.yaml` 已被 gitignore；文档和日志里也不回显密码）。

## 八、出问题按症状查

| 你看到的现象 | 先看这里 | 想更快的话 |
|---|---|---|
| 报「找不到前台小程序webview」 | 手机上小程序没在前台（框架开跑前会拦） | 微信里把小程序点开 |

| 报「找不到底部 tab」 | [踩坑记录.md](踩坑记录.md)（坑 15/17） | 用例首尾各加一步「回到首页」 |
| 表格填错报第几行 | [使用手册-零基础.md](使用手册-零基础.md) 第六节 | 按行号改，改完重跑 |
| 动作下拉框是空的 | 已修（坑 30）；再遇到就先跑 `python tools/export_cases.py --dropdown` | — |
| 单条红、全量不红 | [踩坑记录.md](踩坑记录.md)（坑 14/19） | 先按真问题查，再单条复跑 |
| 数据好像被弄脏了 | `docs/待owner拍板.md`（复位口径） | 用 `tools/` 里的复位工具，默认只预览 |

## 九、什么时候必须找 AI（不用硬扛的四种情况）

1. **小程序改版**，选择器失效（页面对象要改，改动面比看起来大）；
2. **要加新动作**（白名单要四处同步，漏一处表就用不了）；
3. **闸门报红看不懂**（它给的提示就是给你贴给 AI 的）;
4. **要做"会写数据"的新用例**，但还没有复位手段 —— 这种事必须先想清"怎么撤回"。

反过来说，下面这些**你完全可以自己做**：加/改用例、调整期望值、跑全量或单条、看报告、
开写开关跑写链路、按症状表自己排查常见问题。

## 十、给自己排的一条学习路线

| 天 | 做什么 | 目的 |
|---|---|---|
| 1 | 跑一次全量，只看结果三处 | 熟悉"跑完什么样" |
| 2 | `-k` 单跑一条，打开报告看每一步截图 | 熟悉报告 |
| 3 | 把一条用例的期望值故意改错，跑一次看它红，再改回来 | **学会反向验证**（最重要的一天） |
| 4 | 照第 4 节的骨架，自己加一条新用例 | 学会写用例 |
| 5 | 读 [动作清单-分类.md](动作清单-分类.md) + 踩坑记录文首索引 | 知道有哪些动作、踩过哪些坑 |
| 6 | 跑 `python scripts/verify-all.py`，对照第六节的表 | 知道闸门在保护什么 |
| 7 | 把它整理成"一句话总结"讲给别人听 | 讲得出来才算真会 |

> 一句总结：**表格写法是内容，动作是词汇，检查是断言，闸门是安全带。**
> 你负责"写清楚要什么"，框架负责"跑清楚、说老实话"。
