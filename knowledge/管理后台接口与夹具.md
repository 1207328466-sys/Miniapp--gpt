# 管理后台接口与夹具（怎么"从后台配一条数据"）

> 为什么有这份文档：有几条需求/缺陷**不配数据就测不动**，而它们的字段**不在我们这个库里**：
> · 置顶帖（缺陷 713367194）：`post` 表 32 个列里**没有**任何置顶字段，全库列名带 `top/pin` 的地方
>   也没有帖子的（只有评论表的 `top_flag`、`recommend_user.is_top`、`simulation_case.top_flag`）；
> · 案例评论：库里只有 `simulation_case` 相关的读接口，没有"造评论"的入口。
> 所以要走**管理后台**。这份文档记的是 2026/10/15 实测打通的路径、扒出来的接口、以及没走通的那一步。

## 一、进门：拿管理后台 token（**已打通**）

| 项 | 值 |
|---|---|

**怎么取**（本机可行、无需下载浏览器）：

```python

# 账号框 input[type=text] / 密码框 input[type=password] / 登录按钮文案是「登 录」（antd 两字按钮中间有空格）
page.evaluate("t => localStorage.setItem('token', JSON.stringify({dataType:'string', content:t}))", token)
```

> 2026/10/15 那三个一次性脚本写在 `%TEMP%` 下（**不进仓库**，用完即弃）：一个"登录取 token"（把裸 JWT
> 落到 %TEMP% 下的一个 txt，后面复用）、一个"带 token 打 GET/POST"（**POST 默认只预览，加 --apply 才真发**）、
> 一个"扒前端 bundle 找接口"。要重做的话照上面那几步即可，逻辑都在本文里。

**自检**：`GET /api/manager/user/check/token` 返回 `code:200` 且能看到 `userName/authorities` 就说明 token 可用。

## 二、接口怎么发现（Swagger 是空壳）

后台是 SPA，整个前端就**一个** ~4.5MB 的入口 JS（`/admin/assets/index-*.js`，文件名带 hash）。
接口都写成模板串：`` axiosInstance(`${baseUrl}/manager/xxx`, {method:"POST", data:a}) ``。
所以：

1. 拉那个 index JS（`requests.get` 即可，静态资源不要 token）；
2. 正则扫 `baseUrl\}\s*(/manager/[A-Za-z0-9_\-/${}.:]+)` —— 参数段是 `${a}`，别用引号截断（会漏一大半）；
3. 用关键词定位"哪个函数/哪个字段"：搜中文（`置顶`）、搜函数名（`topPost`），上下文里通常就写着请求体形状。

本次扫到 **248 个** `/manager/**` 路径。跟我们相关的：

| 用途 | 接口 | 请求体 / 说明 |
|---|---|---|
| 帖子列表 | `POST /manager/postings/getPostList` | `{pageNumber, pageSize, sortBy, sortOrder, ...过滤}`；返回 `records[].{id,title,userId,isTop,status,managerStatus,...}` |
| **帖子置顶/取消** | `POST /manager/postings/topPost` | `{id, isTop: 0\|1}` —— 前端原文：`onConfirm: ()=>Z({id: oe.id, isTop: oe.isTop==0?1:0})`，按钮文案「置顶 / 取消置顶」 |
| 案例列表 | `POST /manager/simulationCase/getList` | 案例库管理（详情/复制/评论都在这一族） |
| 案例评论 | `POST /manager/simulationCase/getCommentList`（参数 `{pageNumber,pageSize,id:案例id}`）、`deleteCommentByManager` | ⚠️ **只有查和删，没有"造评论"** → 夹具只能落到库里（见下面第五节） |
| 案例置顶 | `POST /manager/simulationCase/updateCaseTopFlag` | 案例自身的置顶 |
| 帖子评论 | `/manager/comment/getCommentList`、`blockComment`、`deleteComment` | |
| 专栏评论置顶 | `/manager/interlocutionColumnComment/updateTopStatus` | |
| 文件 | `/manager/file/ossUpload`、`staticUploadFile` | 造"带图评论"可能要用 |
| **护航服务（压铸护航服务）** | `POST/GET /manager/escort/<模块>/{list,detail,create,update,delete,updateStatus,sort}`，模块有 `base`(基础信息) / `content`(服务内容) / `advantage`(服务优势) / `scene`(适用场景) / **`case`(行业案例)** / `package`(套餐) / `faq`(常见问题)；另有 `escort/appointment/*`（预约） | **2026/10/16 扫到并实测**。形状（从 bundle 抄的）：`list/detail` 是 **GET + query**（`?pageNumber=&pageSize=&sort=&order=`），`create/update` 是 POST + JSON，`updateStatus` 是 POST + `?id=&status=`。行业案例的字段：`{title, tag, description, bgImageFileId, status, sort, segments}` —— **`description` 就是小程序卡片上那句描述** |

## 三、置顶帖：**已打通**（含"怎么刷新才看得到"这条关键事实）

**接口**：`POST /manager/postings/topPost {id, isTop}` —— `isTop: 1` 置顶 / `0` 取消。
语义是**"设成目标值"**，不是 toggle（后台前端原文：`onConfirm: ()=>Z({id, isTop: isTop==0?1:0})`）。
回读用 `POST /manager/postings/getPostList`（返回 `records[].{id,title,userId,isTop,status,...}`）。

**工具**：`tools/post_top_tool.py`（默认只预览、`--yes` 才真写、`--pin/--unpin`、按标题找时**重名拒绝**）。
token 逻辑见本文第一节；没 token 时它会告诉你怎么取（`--login`）。

**端到端实测（2026/10/15 首次，2026/10/16 补齐）**：接口置顶/取消都是**立刻生效**的，
问题只在"小程序端怎么才会重新取数"：

| 做法 | 结果 |
|---|---|
| **下拉刷新**（动作「下拉刷新」，2026/10/16 起首选） | ✅ 立刻反映：置顶 → **一次下拉，约 1 秒**第一条就是「置顶 兄弟 xiba 1」；取消置顶同理（全程 1~3 秒，不用离开这一页） |
| 「进用户中心 → 回首页」 | 十几分钟都还是旧列表 —— **那不是服务端缓存，是这份刷新没生效**（我一开始就是这么误判的） |
| 调切换动作、但**本来就在「最新提问」** | 幂等："已选中筛选 tab「最新提问」，无需切换" → **等于没刷新** |
| **真切 tab**（先切到「推荐」再切回「最新提问」） | ✅ 立刻反映：16:18:52 置顶 → 16:20 已在第一位；取消置顶也**立刻**摘掉「置顶」 |

> ⚠️ **这条需求最容易踩的坑就是这个**：用"看起来像刷新"的动作去刷新（幂等导航、重进同一栏），
> 会得到"没生效"的假象，甚至误判成产品 bug / 服务端缓存。详见 `docs/踩坑记录.md` 坑 49 与坑 53
>（坑 53 里还有一份**逐 180ms 采样**的刷新过程时间线：转圈的点出现又停、卡片数 10 → 0 → 10）。
> 另注：切回来要**等列表重新渲染出卡片**再读（实测切回来 2.5 秒时读到 0 张卡）。

**回归用例**：`test_case/suprecast_app/test_top_post.js`（缺陷 713367194，**自摆自收 + 正反两向**）
—— 从信息流里挑一条**看得见、后台能唯一定位、当前未置顶**的帖子 → 置顶 →
**下拉刷新**（不灵退回真切 tab）+ 短轮询（默认 5 分钟、每 20 秒一轮）等它出现在第一条并带「置顶」→
取消置顶 → **再验一次「置顶」被摘掉**。跑法：`$env:UITEST_ALLOW_SUBMIT="1"; python run.py -k 置顶帖`
（开关没开就记「跳过」）。实测一轮约 **100 秒**全过。

**还有一处待查（不影响用例结论）**：置顶状态**不在这套库里**（`post` 表 32 列全查过、全库带 top/pin 的列也逐个查过，
帖子侧没有置顶字段）→ 它记在管理端自己的存储里；另外观察到我手动置顶过的 1035 过一会儿自己变回 `isTop=0`，
怀疑置顶有**有效期/被别的写者改过**，需要时再花时间确认。

## 四、案例评论（带图评论）：**夹具落到库里**

缺陷 713369819：「发布带图的评论到案例详情，查看时图片未显示」。要回归它，先得有"一条带图评论"。

**为什么不能"造"得很轻松**：小程序端发评论要过微信的**原生图片选择器**（框架驱动不了）；
管理后台只有"查评论 / 删评论"，**没有造评论的接口**。所以夹具直接落库 —— 但口径是**拿真实数据反查出来的**，不是猜的：

| 东西 | 表 | 口径（2026/10/15 实测） |
|---|---|---|
| 评论本体 | `locution_comment` | `biz_id`=案例id、`clazz_type`=1（案例库）、`status`=3、`manager_status`=0、`is_deleted`=0、`level`=1、`parent_id`=0 |
| 评论里的图 | `upload_file` | `biz_id`=**评论id**、**`biz_type`=2（评论）**、`file_type`=7，带 width/height/file_size |

> ⚠️ **`upload_file.biz_id` 会跟别的业务撞车**：同一个 id 上既有"案例自己的图"（`biz_type=1`、`file_type=4`）
> 也有别的业务的行（`biz_type=10/12/25…`）。所以：
> 1. 抄图片行时**只认 `biz_type=2 + file_type=7` 那种**（第一版抄了 `biz_type=1` 的，后台接口 `img` 还是 null —— 实测踩过）；
> 2. 删我们造的数据时**必须带自己的标记**（工具用 `file_name` 认领），**不能只按 `biz_id` 删** —— 会把别人的行一起删掉。

**工具**：`tools/case_comment_tool.py`（`--add/--remove/--list`，默认只预览、`--yes` 才写、
按内容里的标记 `UITEST带图评论` 认领自己造的那条、库名不像测试库就拒绝）。
**回归用例**：`test_case/suprecast_app/test_case_comment.js`（自摆自收：造 → 打开案例详情断言图渲染出来 → 删）。
判据不是"评论在不在"，而是**图有没有画出来**：在评论条目（`class` 带 `comment-item`）的正文区
（`comment-content`）里要有 `wx-image`、**渲染尺寸 > 20×20**、`src` 是 http(s)（头像那个 33×33 不算）。
实测：评论 23 → 24、`93×93` 的 OSS 图渲染出来、删完回到 23；**把图那行删掉再跑，断言会红**（正反都验过）。

## 五、纪律

1. **凭据与 token 一律不打印**（只打长度、用户名、过期时间）；token 文件放 `%TEMP%`，不进仓库；
2. **写操作先预览**（`--apply`/`--yes` 才真写）、**写完回读**、**跑完还原** —— 置顶这类"改了别人也看得见"的字段尤其要还原；
3. 扒 bundle、看列表都只 `GET`；
4. alpha 上有**并发写者**（这次就有人在造活动、发帖子）→ 一律**先现读再断言**，不拿旧快照说话；
5. **删夹具数据要带自己的标记**：共享表里 `biz_id` 会撞车，只按 id 删会误伤别人的数据。
