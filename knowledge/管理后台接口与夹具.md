## 一、进门：拿管理后台 token（**已打通**）

| 项 | 值 |
|---|---|
| 后台地址 | `https://zhuwen-alpha.supreium.com/admin` |
| 接口基址 | `https://zhuwen-alpha.supreium.com/api` + `/manager/**` |
| 鉴权 | 中台 SSO。请求头 `Authorization: <裸 JWT>`（**不是** `Bearer xxx`） |
| 凭据 | 在**同事的仓** `C:\Users\admin\Desktop\miniapp-flow\.env`：`TEST_ADMIN_USERNAME` / `TEST_ADMIN_PASSWORD`（**不打印、不入库**） |
| token 存放 | 后台前端把它放在 `localStorage.token`，值是 JSON 包装 `{"dataType":"string","content":"<JWT>","datetime":…}` —— **用之前必须解出 `content`**，否则会 401 `Token Validation Failed` |

**怎么取**（本机可行、无需下载浏览器）：

```python
# python + playwright + 系统自带 Edge（实测 Edge 155）
browser = p.chromium.launch(channel="msedge", headless=True)
page.goto("https://zhuwen-alpha.supreium.com/admin")     # 会跳到中台 SSO 登录页
# 账号框 input[type=text] / 密码框 input[type=password] / 登录按钮文案是「登 录」（antd 两字按钮中间有空格）
page.evaluate("t => localStorage.setItem('token', JSON.stringify({dataType:'string', content:t}))", token)
```

> 2026/10/15 那三个一次性脚本写在 `%TEMP%` 下（**不进仓库**，用完即弃）：一个"登录取 token"（把裸 JWT
> 落到 %TEMP% 下的一个 txt，后面复用）、一个"带 token 打 GET/POST"（**POST 默认只预览，加 --apply 才真发**）、
> 一个"扒前端 bundle 找接口"。要重做的话照上面那几步即可，逻辑都在本文里。

**自检**：`GET /api/manager/user/check/token` 返回 `code:200` 且能看到 `userName/authorities` 就说明 token 可用。

## 二、接口怎么发现（Swagger 是空壳）

后台是 SPA，整个前端就**一个** ~4.5MB 的入口 JS（`/admin/assets/index-*.js`，文件名带 hash）。
接口都写成模板串：`` axiosInstance(`${baseUrl}/manager/xxx`, {method:"POST", data:a}) ``。
所以：

1. 拉那个 index JS（`requests.get` 即可，静态资源不要 token）；
2. 正则扫 `baseUrl\}\s*(/manager/[A-Za-z0-9_\-/${}.:]+)` —— 参数段是 `${a}`，别用引号截断（会漏一大半）；
3. 用关键词定位"哪个函数/哪个字段"：搜中文（`置顶`）、搜函数名（`topPost`），上下文里通常就写着请求体形状。

本次扫到 **248 个** `/manager/**` 路径。跟我们相关的：

| 用途 | 接口 | 请求体 / 说明 |
|---|---|---|
| 帖子列表 | `POST /manager/postings/getPostList` | `{pageNumber, pageSize, sortBy, sortOrder, ...过滤}`；返回 `records[].{id,title,userId,isTop,status,managerStatus,...}` |
| **帖子置顶/取消** | `POST /manager/postings/topPost` | `{id, isTop: 0\|1}` —— 前端原文：`onConfirm: ()=>Z({id: oe.id, isTop: oe.isTop==0?1:0})`，按钮文案「置顶 / 取消置顶」 |
| 案例列表 | `POST /manager/simulationCase/getList` | 案例库管理（详情/复制/评论都在这一族） |
| 案例评论 | `POST /manager/simulationCase/getCommentList`、`deleteCommentByManager` | ⚠️ **只有查和删，没有"造评论"** → 案例评论要在**小程序端**发 |
| 案例置顶 | `POST /manager/simulationCase/updateCaseTopFlag` | 案例自身的置顶 |
| 帖子评论 | `/manager/comment/getCommentList`、`blockComment`、`deleteComment` | |
| 专栏评论置顶 | `/manager/interlocutionColumnComment/updateTopStatus` | |
| 文件 | `/manager/file/ossUpload`、`staticUploadFile` | 造"带图评论"可能要用 |

## 三、置顶帖：**卡在最后一步**（诚实记录，别当成已打通）

**做到的**：

1. `POST /manager/postings/topPost {id:1064, isTop:1}` → 返回 200；再查 `getPostList`，`isTop` 从 **0 → 1** ✓
   （回读当证据，不是"发了请求就算数"）；
2. 换一条**本来就在信息流里**的帖子再验（id=1035「兄弟」，作者 xiba）：置顶 → `isTop=1` ✓；
3. 按 owner 要求**跑完还原**：两条都 `isTop=0`，现在没有置顶帖。

**没做到的**：小程序「最新提问」里**看不到置顶效果** ——

* 置顶后进信息流（先离开首页再回来强制重新取数，避坑 43）滚 6 屏，**既没有该贴的置顶标记，也没有任何「置顶」字样**；
  帖子 1035 照旧按原位置排在信息流里（它是第 3 张卡）；
* 判断依据：`flow-item` 的 DOM 顺序 + 每屏 `document.body.innerText` 里搜「置顶」；
* 结论：**置顶状态不在这套库里**（`post` 表没有该字段、全库也没有），所以后台的置顶是记在**别的存储**（管理端自己的库/缓存）里；
  而小程序端的信息流**没有把这份置顶读出来**——要么手机上的小程序版本比修好的那版旧，要么服务端有缓存 TTL，要么这条链路本身还有问题。

**下一步（留给下一个人，带上证据再判断）**：

1. 先确认**手机上装的测试环境小程序版本**是否包含 713367194 的修复（问开发 / 看发布记录）；
2. 置顶之后**等一个缓存周期**（几分钟）再看，排除 TTL；
3. 抓小程序端信息流接口的返回（本仓 `test_case/diagnostic/dump_page.js` 只能看 DOM，要看接口得用 flow 仓的抓包路子），
   看返回里到底有没有 `isTop` 字段——有字段但没渲染 = 前端问题；没字段 = 服务端没把置顶带出来；
4. 真要写成用例，就照 `ZW_030`（屏蔽礼品分类）那套**自摆自收**：用例里先置顶 → 断言 → 取消置顶；
   动作可以挂在 `tools/` 下一个"调管理后台接口"的工具上（token 逻辑见第一节）。

## 四、纪律

1. **凭据与 token 一律不打印**（只打长度、用户名、过期时间）；token 文件放 `%TEMP%`，不进仓库；
2. **写操作先预览**（`--apply` 才真发）、**写完回读**、**跑完还原** —— 置顶这类"改了别人也看得见"的字段尤其要还原；
3. 扒 bundle、看列表都只 `GET`；
4. alpha 上有**并发写者**（这次就有人在造活动、发帖子）→ 一律**先现读再断言**，不拿旧快照说话。
