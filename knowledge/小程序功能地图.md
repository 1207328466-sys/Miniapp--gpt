### 2.5 积分系统（**跨迭代的最大一块**）

接入积分中台与积分规则、积分商城首页（含活动、热门推荐、榜单）、积分明细、积分获取（任务）、

虚拟类礼品兑换、实物类礼品兑换、取消订单、地址选择器组件、积分榜单（支持分享）、
积分助手、订单发货与新订单短信提醒、回到顶部按钮、页面风格优化、埋点分析。

> 与测试的关系：**积分是最容易被自动化影响的真实数据**（这台设备用真实账号）。
> 涉及兑换/抽奖/签到/下单的用例，默认不要动 —— 见 `环境与目标小程序.md` 的数据安全一节。

## 3. 与技术结构的对应关系

| 概念 | 对应 |
|---|---|
| 底部 tab | 有问必答 \| 学习中心 \| ⊕ \| 设计专区 \| 我的（`我的` = 用户中心） |
| 二级页（**没有底部 tab 栏**） | 专栏详情页、搜索页、话题列表页、答题活动页…… 用例自导航必须能退出一级页，见 `base.ensureOnTabPage` |
| 页面对象 | `app_sub_function/suprecast_app/pages/`：`learnCenter` / `columnDetail` / `userCenter` / `qaPage` / `quizPage` |
| 活动卡 | 首页横向活动卡区（角标文本如「答题·官方」「图文·官方」），**角标会随时间变化** —— 找不到时先等再判前置条件不满足 |

## 4. 还没写用例的功能域（按"值得自动化"排序的建议）

1. **互动专栏订阅**：已有页面对象可读状态，补断言成本最低，且订阅是有状态的操作（**会改数据**）
2. **有问必答帖子详情 / 收藏**：核心社区链路，读多写少，适合自动化
3. **积分明细 / 积分榜单**：纯只读页面，风险最低
4. **培训课程列表 → 详情**：与专栏链路同构，可复用页面对象写法
5. **AI 助手**：交互非确定性高，自动化收益低，建议人工验收
